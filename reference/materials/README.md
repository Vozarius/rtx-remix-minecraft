# Материалы из reference

`sources/assets/` — исходные PNG текстур, используемых статическими моделями блоков,
и найденные текстуры жидкостей. Оригиналы и анимационные `.png.mcmeta` сохранены.
`emission-candidates/assets/` — удобная выборка для рисования масок свечения.
`fluid-previews/assets/` — водяная анимация с цветом и средней альфой соответствующего оригинала.

В `catalog-static.json` есть блоки, использующие текстуру, источник JAR, прозрачность,
средний RGBA и путь будущей маски. `fluids-static.json` содержит выборку текстур жидкостей.
Статический экспорт содержит запас: свечение и жидкости определены по именам ресурсов,
поэтому это кандидаты, а не подтверждённый список зарегистрированных светящихся блоков.
Пустые служебные PNG в пространстве `create:fluid` из TFMG пропущены;
одноимённые непустые текстуры `tfmg:fluid` выгружены.

При запуске мод строит точный каталог по реально зарегистрированным состояниям блоков,
их моделям и FluidType. Его отчёт и оригиналы активных ресурс-паков находятся в
`.minecraft/rtx-remix/reference/materials/catalog.json` и `sources/` рядом.
Свойство JVM `-Drtxremix.materialReferenceDirectory=<путь>` меняет эту папку.
Поле `needs_emission_mask` указывает текстуры светящихся моделей без готовой маски.
Текстуры корпуса лампы тоже попадают в список: им достаточно полностью чёрной маски.

## Как рисовать маски

Создай PNG того же размера и расположения кадров, что у исходника.
Белый пиксель — свечение исходным цветом; чёрный — без свечения;
серый — промежуточная сила. Альфа маски дополнительно ослабляет свечение.
Не используй прозрачный белый для включённого света: нужна непрозрачная белая область.

Название: `assets/<namespace>/textures/<путь_исходника>_e.png`.
Например: `assets/create/textures/block/blaze_burner/blaze_burner_lit_e.png`.
Добавь эти файлы в обычный ресурс-пак с `pack.mcmeta` для Minecraft 1.21.1
(`pack_format: 34`). Маска `_e.png` имеет приоритет над свечением LabPBR `_s.png`.
Без `_e` сохраняется существующее LabPBR-свечение. Нулевой mask-пиксель выключает
свечение поверхности. Мощность автоматического аналитического света умножается на среднее
покрытие масок светящихся текстур блока; полностью чёрная маска выключает этот свет.
Явные правила света имеют приоритет и не изменяются маской.
Для отключения/замены аналитического света используй правила `rtx_remix/block_lights`.

## Клиентский рендерер и Copper Beacon

Основной полный JAR `rtx-remix-renderer-neoforge-…-win64.jar` нужен только клиенту.
Он не регистрирует блоки, предметы, меню, сетевые пакеты или типы частиц.
Визуальная пена создаётся локально.

Настоящий `rtx-remix-renderer:copper_beacon` вынесен в маленький отдельный JAR
`rtx-remix-content-neoforge-….jar`. Для миров с этим блоком он нужен серверу
и клиентам, а для одиночного мира — клиенту. Сам рендерер на сервер не нужен.
Существующие идентификаторы и NBT Copper Beacon сохранены. Не открывай старый мир
с Copper Beacon без контентного JAR: игра не сможет найти его блоки.


## Подключённые маски

Все 7 изображений из `emission-candidates/emission_masks/` подключены в базовые ресурсы
мода: 27 точных привязок находятся в `emission-mask-mapping.json`.
Одна маска Create Deco используется для четырёх включённых вариантов cage lamp;
выключенные варианты не затронуты. У headlight дополнительно подключены включённая
текстура и 16 цветных вариантов. Белая область `[22, 3, 8, 8]` исходной маски перенесена
в `[0, 0, 8, 8]` их 16×16 развёртки; исходная 32×32 маска не изменена.
Поля `source_region` / `destination_region` в манифесте описывают этот перенос.
Ресурс-пак пользователя может заменить эти `_e.png`.

Headlight теперь имеет собственный направленный свет для каждой установленной лампы,
с учётом ориентации, красителя и адресации ComputerCraft. Свет следует за contraption
и родительским sublevel. Переключение лампы не пересоздаёт её нативный ресурс каждый раз.

## Генератор нормалей и высоты

`packaging/generate_surface_maps.py` — самостоятельный пакетный генератор на Python
с Pillow и numpy. Из корня репозитория:

```powershell
python packaging/generate_surface_maps.py --strength 1 --depth 0.12
```

В `generated-surface-maps/assets/` подготовлены 5932 набора по исходным текстурам
из каталога: `_normal.png` (RGB), `_height.png` (серый) и `_n.png` (LabPBR:
RG — нормаль, B — белое AO, A — высота). Анимационные кадры обрабатываются отдельно,
границы тайля замкнуты, прозрачные пиксели не создают выступающий контур.
Цветовая яркость даёт приближение рельефа, а не восстанавливает геометрию модели.

Рендерер также создаёт эти карты автоматически для загруженных текстур без `_n`;
копировать выгрузку в ресурс-пак не требуется. В настройках RTX → Materials:
«Автонормали» — 0..4, «Авторельеф» — 0..1. Ноль выключает соответствующий эффект.
Параметры применяются при закрытии настроек с одной пересборкой материалов и мира.
Готовые `_n` ресурс-пака имеют приоритет. Автоматический рельеф не наносится на стекло;
авторские нормали стекла сохраняются.

## Жидкости

`fluid-textures/assets/` содержит 340 перекрашенных анимаций из статической выборки.
`fluid-textures/catalog.json` указывает исходный средний RGBA и выбранную основу.
Это выборка текстур, в неё могут попадать изображения резервуаров и окон;
количество не означает число зарегистрированных жидкостей.

Основа — ванильная вода; для Aeronautics и Enchantment Industry — ванильная лава.
Ванильная лава сохраняет лавовую основу. Средний цвет и альфа берутся из оригинала,
контраст возле насыщения уменьшается, чтобы обрезанные блики не сдвигали средний цвет.
Рендерер выбирает материал по зарегистрированному типу жидкости, включая жидкости
с общим спрайтом воды, и использует его для ландшафта и Create FluidRenderHelper
(резервуары, движущиеся механизмы). Исходные vertex tint/alpha сохраняются.
Точный список активных типов и их основ экспортируется при запуске в
`.minecraft/rtx-remix/reference/materials/registered-fluids.json`.
